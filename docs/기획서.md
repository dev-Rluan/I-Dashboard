# I-Dashboard 기획서

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | I-Dashboard (Infrastructure Dashboard) |
| 목적 | 서버 인프라 상태를 실시간으로 시각화하여 운영 효율 향상 |
| 실행 방식 | CLI(TUI) 직접 실행 또는 Docker로 GUI 웹 대시보드 구동 |
| 대상 OS | Linux, Windows, macOS |
| 대상 사용자 | 서버 운영자, DevOps 엔지니어 |

### 2-1. CLI 버전
- 터미널에서 `python cli/main.py` 로 즉시 실행
- SSH 접속만으로 확인 가능, 의존성 최소화
- `rich` 라이브러리 기반 TUI, 키보드 네비게이션
- Linux / Windows / macOS 모두 동작

### 2-2. GUI 버전
- Docker Compose 한 줄로 실행: `docker-compose up -d`
- 웹 브라우저로 접근 (`http://서버IP:3000`)
- FastAPI 백엔드가 `core/` 모듈 호출 → REST API / WebSocket 노출
- React + Vite 프론트엔드, 실시간 차트 및 테이블

## 3. 크로스 플랫폼 지원 전략

### OS별 기능 구현 방식

| 기능 | Linux | Windows | macOS |
|------|-------|---------|-------|
| **포트 수집** | `ss -tuln` | `netstat -ano` | `netstat -anv` |
| **방화벽** | `ufw` / `iptables` / `firewalld` | `netsh advfirewall` | `pfctl` |
| **서비스** | `systemctl` | `sc query` / WMI | `launchctl list` |
| **로그** | `/var/log/` | Windows Event Log (`wevtutil`) | `/var/log/` + unified log |
| **리소스** | `psutil` ✅ | `psutil` ✅ | `psutil` ✅ |
| **네트워크** | `psutil` ✅ | `psutil` ✅ | `psutil` ✅ |
| **프로세스** | `psutil` ✅ | `psutil` ✅ | `psutil` ✅ |
| **도커** | Docker CLI ✅ | Docker CLI ✅ | Docker CLI ✅ |

### 추상화 레이어 패턴

```python
# core/platform/__init__.py
import platform

def get_platform():
    os = platform.system()
    if os == "Linux":   return LinuxPlatform()
    if os == "Windows": return WindowsPlatform()
    if os == "Darwin":  return MacOSPlatform()
    raise UnsupportedPlatformError(os)
```

각 `core/*.py` 모듈은 `get_platform()` 을 통해 OS별 구현체를 주입받아 사용한다.  
기능이 지원되지 않는 OS에서는 빈 결과를 반환하며 앱은 계속 동작한다.

### Docker 내부 실행 시 주의사항

GUI를 Docker로 실행할 때 **호스트 머신** 정보를 수집하려면 아래 마운트가 필요하다:

```yaml
volumes:
  - /proc:/host/proc:ro        # 호스트 프로세스/리소스
  - /sys:/host/sys:ro          # 시스템 정보
  - /var/run/docker.sock:/var/run/docker.sock:ro  # 도커 소켓
network_mode: host             # 호스트 네트워크 정보 수집
```

Windows / macOS Docker Desktop 환경에서는 호스트 마운트 제약으로 일부 기능이 제한될 수 있으며, 대시보드에 안내 메시지를 표시한다.

## 4. 기능 명세

### 4-1. 포트 스캐너 (Port Scanner) ★ 핵심
- 열린 포트 / 닫힌 포트 시각적 표시 (초록 / 빨강)
- 포트별 서비스명 자동 매핑 (22=SSH, 80=HTTP, 443=HTTPS 등)
- Well-known / Registered / Dynamic 포트 범위 구분
- 포트 클릭(GUI) / 선택(CLI) 시 상세 정보 표시 (PID, 프로세스명, 사용자)
- 커스텀 포트 범위 스캔

### 4-2. 방화벽 상태 (Firewall Status) ★ 핵심
- Linux: `ufw` / `iptables` / `firewalld` 자동 감지
- Windows: Windows Defender 방화벽 (`netsh advfirewall`)
- macOS: `pfctl` (pf firewall)
- 인바운드 / 아웃바운드 규칙 테이블 표시
- 허용(ACCEPT) / 차단(DROP/REJECT) 색상 구분
- 방화벽 활성화 / 비활성화 상태 배지

### 4-3. 시스템 리소스 (System Resources)
- CPU: 코어별 사용률 실시간 게이지
- 메모리: 사용량 / 가용량 / 캐시 구분
- 디스크: 마운트 포인트(Linux/macOS) / 드라이브(Windows)별 용량 및 I/O 속도
- 스왑 사용률

### 4-4. 네트워크 인터페이스 (Network Interfaces)
- 인터페이스별 IP, MAC, 상태 (UP / DOWN)
- 실시간 인바운드 / 아웃바운드 트래픽 그래프
- 패킷 손실률, 에러 카운트

### 4-5. 프로세스 모니터 (Process Monitor)
- CPU / 메모리 상위 프로세스 순위 표
- 프로세스 상태 (running / sleeping / zombie 등)
- 검색 및 필터 기능

### 4-6. 시스템 서비스 (Service Manager)
- Linux: `systemctl` — active / failed / inactive 분류
- Windows: Windows Services (`sc query`) — Running / Stopped / Failed
- macOS: `launchctl` — 서비스 상태
- 실패한 서비스 알림 강조
- 서비스별 최근 로그 (지원 시)

### 4-7. 로그 뷰어 (Log Viewer)
- Linux: `/var/log/syslog`, `/var/log/auth.log`, nginx/apache 로그
- Windows: Windows Event Log (Application, System, Security)
- macOS: `/var/log/system.log`, unified log (`log show`)
- 키워드 검색, ERROR / WARN 필터링
- SSH 로그인 시도 이력 (brute-force 패턴 감지, Linux/macOS)

### 4-8. 도커 컨테이너 (Docker Monitor) *(선택)*
- 실행 중인 컨테이너 목록 및 상태
- 컨테이너별 CPU / 메모리 사용량
- 컨테이너 로그 확인
- Docker 미설치 시 기능 비활성화 (앱 정상 동작)

## 6. 기술 스택

| 영역 | 기술 | 이유 |
|------|------|------|
| 플랫폼 추상화 | `platform.system()` + 전략 패턴 | OS 분기 한 곳에서 관리 |
| 공통 수집 | Python + `psutil` | 크로스 플랫폼 리소스/프로세스/네트워크 |
| 포트 / 방화벽 / 서비스 | `subprocess` + OS별 명령어 | OS 네이티브 정보 정확하게 수집 |
| CLI TUI | `rich` | 컬러, 테이블, 패널, Windows 터미널 지원 |
| Backend | FastAPI | 빠른 개발, WebSocket 내장 |
| Frontend | React + Vite + TypeScript | SPA, 컴포넌트 재사용성 |
| 차트 | Recharts | React 친화적 |
| 스타일 | Tailwind CSS | 다크모드 UI 빠른 구성 |
| 컨테이너 | Docker + Docker Compose | 환경 독립적 GUI 배포 |
| 리버스 프록시 | Nginx | 정적 파일 서빙 + API 프록시 |

## 8. 보안 고려사항

- 대시보드에 Basic Auth 또는 JWT 로그인 적용 (외부 노출 방지)
- 읽기 전용 운영 — 서버 제어 기능 없음, 모니터링만
- HTTPS 설정 권장 (self-signed cert 지원, Let's Encrypt 연동 가이드 제공)
- 민감 정보 (비밀번호, 개인키) 표시 제외
- 방화벽 수집은 관리자 권한 필요 시 명시적 안내
- Docker 소켓 마운트는 읽기 전용 (`:ro`) 으로만 허용
