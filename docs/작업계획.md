# I-Dashboard 작업계획

## 개발 원칙

- `core/` 수집 모듈을 먼저 완성한 뒤 CLI → GUI 순서로 연결
- 각 Phase는 독립적으로 동작 가능한 상태로 완료
- 모든 `core/` 모듈은 Linux / Windows / macOS에서 동작해야 함
- 지원 안 되는 기능은 예외 없이 빈 결과 반환 (앱 중단 금지)
- 커밋 단위: 기능 단위 (파일 단위 X)

---

## Phase 0 — 프로젝트 뼈대 + 크로스 플랫폼 추상화

> 목표: 디렉토리 구조, 의존성, OS 추상화 레이어 세팅

### 0-1. 프로젝트 초기 세팅
- [ ] 디렉토리 구조 생성 (`core/`, `core/platform/`, `cli/`, `gui/`, `docker/`)
- [ ] `requirements.txt` 작성 (psutil, rich, fastapi, uvicorn, websockets)
- [ ] `.gitignore` 작성 (Python, Node, Docker, OS별 파일)
- [ ] `gui/frontend/` Vite + React + TypeScript 초기화

### 0-2. core/platform/ — OS 추상화 레이어
- [ ] `core/platform/__init__.py` — `platform.system()` 감지 후 구현체 반환
- [ ] `core/platform/base.py` — 추상 베이스 클래스 (인터페이스 정의)
- [ ] `core/platform/linux.py` — Linux 구현체 스텁
- [ ] `core/platform/windows.py` — Windows 구현체 스텁
- [ ] `core/platform/macos.py` — macOS 구현체 스텁

### 0-3. Docker 뼈대
- [ ] `docker/Dockerfile.backend` — Python + FastAPI 이미지
- [ ] `docker/Dockerfile.frontend` — Node 빌드 + Nginx 서빙
- [ ] `docker/nginx.conf` — 정적 파일 서빙 + `/api` 프록시
- [ ] `docker-compose.yml` — 프로덕션 (호스트 마운트 포함)
- [ ] `docker-compose.dev.yml` — 개발 환경 (핫 리로드)
- [ ] `.env.example` — 환경변수 템플릿

**완료 기준**: `docker-compose up --build` 가 오류 없이 실행됨 (빈 응답이라도)

## Phase 1 — 포트 스캐너 + 방화벽 (core + CLI)

> 목표: 포트 스캔 · 방화벽 상태를 CLI에서 확인 가능한 상태

### 1-1. core/ports.py
- [ ] Linux: `ss -tuln` 파싱
- [ ] Windows: `netstat -ano` 파싱
- [ ] macOS: `netstat -anv` 파싱
- [ ] PID / 프로세스명 / 사용자 매핑 (`psutil`, 크로스 플랫폼)
- [ ] Well-known 포트 서비스명 딕셔너리

### 1-2. core/firewall.py
- [ ] Linux: `ufw` / `iptables` / `firewalld` 자동 감지 및 파싱
- [ ] Windows: `netsh advfirewall show allprofiles` 파싱
- [ ] macOS: `pfctl -s rules` 파싱
- [ ] 방화벽 활성화 상태 조회 (OS별)
- [ ] 인바운드 / 아웃바운드 규칙 통일된 구조로 반환

### 1-3. cli/main.py — Phase 1 뷰
- [ ] `rich` 레이아웃 (사이드 패널 + 메인 영역)
- [ ] 포트 현황 테이블 (열림/닫힘 색상 구분)
- [ ] 방화벽 규칙 테이블
- [ ] 키보드 네비게이션 (q: 종료, r: 새로고침)
- [ ] 자동 갱신 루프 (기본 5초)

**완료 기준**: Linux / Windows / macOS에서 `python cli/main.py` 실행 시 포트 · 방화벽 상태 표시

## Phase 2 — 시스템 리소스 + 네트워크 (core + CLI 확장)

> 목표: CPU / 메모리 / 디스크 / 네트워크를 CLI에서 실시간 확인

### 2-1. core/resources.py
- [ ] CPU 코어별 사용률 (`psutil.cpu_percent(percpu=True)`)
- [ ] 메모리: 사용 / 가용 / 캐시 / 스왑
- [ ] 디스크: 마운트 포인트(Linux/macOS) / 드라이브 레터(Windows)별 용량, read/write I/O

### 2-2. core/network.py
- [ ] 인터페이스 목록, IP, MAC, UP/DOWN 상태 (`psutil`)
- [ ] 실시간 송수신 바이트 (초당 계산)
- [ ] 패킷 에러 / 드롭 카운트

### 2-3. cli/main.py — Phase 2 뷰 추가
- [ ] 상단 요약 카드 (CPU / MEM / DISK 게이지)
- [ ] 네트워크 인터페이스 테이블
- [ ] 탭 전환 (1: 포트, 2: 방화벽, 3: 리소스, 4: 네트워크)

**완료 기준**: 탭 전환하며 리소스 실시간 확인 가능 (전 OS)

## Phase 3 — 프로세스 · 서비스 (core + CLI 완성)

> 목표: CLI 버전 전체 기능 완성

### 3-1. core/processes.py
- [ ] 전체 프로세스 목록 (PID, 이름, CPU%, MEM%, 상태, 사용자) — `psutil`
- [ ] CPU / 메모리 기준 정렬
- [ ] zombie 프로세스 감지 (Linux/macOS), Not Responding (Windows)

### 3-2. core/services.py
- [ ] Linux: `systemctl list-units` 파싱, `journalctl -u <svc> -n 20`
- [ ] Windows: `sc query` 파싱, Event Log 수집
- [ ] macOS: `launchctl list` 파싱, unified log 수집
- [ ] active / running / failed / stopped 상태를 통일된 enum으로 반환

### 3-3. cli/main.py — Phase 3 뷰 추가
- [ ] 프로세스 상위 10개 테이블 (CPU / MEM 토글)
- [ ] 서비스 목록 (failed / stopped 서비스 빨간색 강조)
- [ ] 서비스 선택 시 로그 팝업
- [ ] `--help` 옵션 제공

**완료 기준**: CLI 버전 전 기능 동작 (전 OS)

## Phase 4 — GUI 백엔드 (FastAPI)

> 목표: core/ 모듈을 REST API + WebSocket으로 노출

### 4-1. gui/backend/ 구조 세팅
- [ ] FastAPI 앱 초기화 (`main.py`)
- [ ] CORS 설정
- [ ] 라우터 분리 (`routers/ports.py`, `routers/resources.py` 등)
- [ ] Pydantic 응답 스키마 정의 (`schemas/`)

### 4-2. REST API 엔드포인트
- [ ] `GET /api/ports` — 포트 목록
- [ ] `GET /api/firewall` — 방화벽 규칙
- [ ] `GET /api/resources` — CPU / MEM / DISK 스냅샷
- [ ] `GET /api/network` — 네트워크 인터페이스
- [ ] `GET /api/processes` — 프로세스 목록
- [ ] `GET /api/services` — 서비스 목록
- [ ] `GET /api/docker` — 컨테이너 목록
- [ ] `GET /api/system/info` — OS / 호스트명 / 플랫폼 정보

### 4-3. WebSocket 엔드포인트
- [ ] `WS /ws/resources` — 리소스 실시간 스트림 (5초 간격)
- [ ] `WS /ws/ports` — 포트 변경 감지 스트림

### 4-4. 인증
- [ ] 환경변수 기반 Basic Auth 미들웨어 (`DASHBOARD_USER`, `DASHBOARD_PASS` 미설정 시 비활성화)

**완료 기준**: `uvicorn gui.backend.main:app` 실행 시 모든 API 응답 확인
