# I-Dashboard 작업계획

## 개발 원칙

- `core/` 수집 모듈을 먼저 완성한 뒤 CLI → GUI 순서로 연결
- 각 Phase는 독립적으로 동작 가능한 상태로 완료
- 커밋 단위: 기능 단위 (파일 단위 X)

---

## Phase 1 — 핵심 수집 모듈 + CLI 기반 구축

> 목표: 포트 스캔 · 방화벽 상태를 CLI에서 확인 가능한 상태

### 1-1. 프로젝트 초기 세팅
- [ ] 디렉토리 구조 생성 (`core/`, `cli/`, `gui/`)
- [ ] `requirements.txt` 작성 (psutil, rich, fastapi, uvicorn 등)
- [ ] `README.md` 작성

### 1-2. core/ports.py
- [ ] 로컬 열린 포트 수집 (`ss -tuln` 파싱)
- [ ] PID / 프로세스명 / 사용자 매핑 (`psutil`)
- [ ] Well-known 포트 서비스명 딕셔너리

### 1-3. core/firewall.py
- [ ] `ufw` / `iptables` / `firewalld` 자동 감지
- [ ] 방화벽 활성화 상태 조회
- [ ] 인바운드 / 아웃바운드 규칙 파싱

### 1-4. cli/main.py — Phase 1 뷰
- [ ] `rich` 레이아웃 (사이드 패널 + 메인 영역)
- [ ] 포트 현황 테이블 (열림/닫힘 색상 구분)
- [ ] 방화벽 규칙 테이블
- [ ] 키보드 네비게이션 (q: 종료, r: 새로고침)
- [ ] 자동 갱신 루프 (기본 5초)

**완료 기준**: `python cli/main.py` 실행 시 포트 · 방화벽 상태가 TUI로 표시됨

---

## Phase 2 — 시스템 리소스 수집 + CLI 확장

> 목표: CPU / 메모리 / 디스크 / 네트워크를 CLI에서 실시간 확인

### 2-1. core/resources.py
- [ ] CPU 코어별 사용률 (`psutil.cpu_percent(percpu=True)`)
- [ ] 메모리: 사용 / 가용 / 캐시 / 스왑
- [ ] 디스크: 마운트 포인트별 용량, read/write I/O

### 2-2. core/network.py
- [ ] 인터페이스 목록, IP, MAC, UP/DOWN 상태
- [ ] 실시간 송수신 바이트 (초당 계산)
- [ ] 패킷 에러 / 드롭 카운트

### 2-3. cli/main.py — Phase 2 뷰 추가
- [ ] 상단 요약 카드 (CPU / MEM / DISK 게이지)
- [ ] 네트워크 인터페이스 테이블
- [ ] 탭 / 페이지 전환 (1: 포트, 2: 방화벽, 3: 리소스, 4: 네트워크)

**완료 기준**: 탭 키로 섹션 전환하며 리소스 실시간 확인 가능

---

## Phase 3 — 프로세스 · 서비스 수집 + CLI 완성

> 목표: CLI 버전 전체 기능 완성

### 3-1. core/processes.py
- [ ] 전체 프로세스 목록 (PID, 이름, CPU%, MEM%, 상태, 사용자)
- [ ] CPU / 메모리 기준 정렬
- [ ] zombie 프로세스 감지

### 3-2. core/services.py
- [ ] `systemctl list-units` 파싱
- [ ] active / failed / inactive 상태 분류
- [ ] 최근 로그 수집 (`journalctl -u <service> -n 20`)

### 3-3. cli/main.py — Phase 3 뷰 추가
- [ ] 프로세스 상위 10개 테이블 (CPU / MEM 토글)
- [ ] 서비스 목록 (failed 서비스 빨간색 강조)
- [ ] 서비스 선택 시 로그 팝업

**완료 기준**: CLI 버전 전 기능 동작, `--help` 옵션 제공

---

## Phase 4 — GUI 백엔드 (FastAPI)

> 목표: core/ 모듈을 REST API + WebSocket으로 노출

### 4-1. gui/backend/ 구조 세팅
- [ ] FastAPI 앱 초기화 (`main.py`)
- [ ] CORS 설정
- [ ] 라우터 분리 (`routers/ports.py`, `routers/resources.py` 등)

### 4-2. REST API 엔드포인트
- [ ] `GET /api/ports` — 포트 목록
- [ ] `GET /api/firewall` — 방화벽 규칙
- [ ] `GET /api/resources` — CPU / MEM / DISK 스냅샷
- [ ] `GET /api/network` — 네트워크 인터페이스
- [ ] `GET /api/processes` — 프로세스 목록
- [ ] `GET /api/services` — 서비스 목록

### 4-3. WebSocket 엔드포인트
- [ ] `WS /ws/resources` — 리소스 실시간 스트림 (5초 간격)
- [ ] `WS /ws/ports` — 포트 변경 감지 스트림

### 4-4. 인증
- [ ] 환경변수 기반 Basic Auth 미들웨어 (선택적 활성화)

**완료 기준**: `uvicorn gui.backend.main:app` 실행 시 모든 API 응답 확인

---

## Phase 5 — GUI 프론트엔드 (React)

> 목표: 웹 대시보드 완성

### 5-1. gui/frontend/ 구조 세팅
- [ ] Vite + React + TypeScript 프로젝트 초기화
- [ ] Tailwind CSS 설정 (다크모드 기본)
- [ ] Recharts 설치
- [ ] API 클라이언트 유틸 (`lib/api.ts`, `lib/ws.ts`)

### 5-2. 공통 컴포넌트
- [ ] `Sidebar` — 메뉴 네비게이션
- [ ] `StatCard` — CPU / MEM / DISK 요약 카드
- [ ] `StatusBadge` — 열림/닫힘, active/failed 배지
- [ ] `DataTable` — 공용 테이블 컴포넌트

### 5-3. 페이지 구현
- [ ] `/` 개요 (Overview) — 요약 카드 + 포트 · 서비스 요약
- [ ] `/ports` — 포트 스캐너 (필터 / 검색)
- [ ] `/firewall` — 방화벽 규칙 테이블
- [ ] `/resources` — CPU / MEM / DISK 실시간 차트
- [ ] `/network` — 네트워크 인터페이스 + 트래픽 그래프
- [ ] `/processes` — 프로세스 테이블 (정렬 / 검색)
- [ ] `/services` — 서비스 목록 (로그 팝업)

### 5-4. 실시간 연동
- [ ] WebSocket hook (`useWebSocket`)
- [ ] 리소스 차트 실시간 업데이트
- [ ] 포트 상태 변경 알림 토스트

**완료 기준**: 브라우저에서 전 페이지 동작, 실시간 갱신 확인

## 커밋 컨벤션

```
feat: 새 기능 추가
fix: 버그 수정
refactor: 리팩토링
docs: 문서 변경
chore: 설정, 의존성 변경
```

예시:
```
feat(core): ports.py 포트 수집 모듈 구현
feat(cli): Phase 1 포트/방화벽 TUI 뷰 추가
feat(gui/backend): FastAPI 포트 API 엔드포인트 추가
```
